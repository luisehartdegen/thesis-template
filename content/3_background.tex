When analysing the process from idea to print, several main steps can be identified. 
The following analysis will focus on the steps from exporting a model to printing, while taking the ideation and design phase as given. 
Once a 3D model has been created, the user exports it using one of several ways Fusion offers.
Depending on the file format, a model can be exported as one file containing multiple objects or one file per object. 
The three formats used most often for 3D printing are STL, 3MF and OBJ, each presenting different advantages and disadvantages. 
The user then opens the exported file in OrcaSlicer. 
Opening the file, or importing it, may cause different dialogs to open, depending on the file type and content. 
So far all steps are fairly simple. 

Next, various printing paramters have to be applied. 
Especially when a model consists of multiple parts, the parameters might vary from one object to the next. 
The easiest step is to apply materials, since this can be done using system or user defined presets. 
Material settings entail for example the nozzle temperature, general printing speed and cooling settings.   
OrcaSlicer actively asks the user, whether they want to save any changes to material parameters they have made, which makes it easy to save either parameters specific to one's printer and filament or even specific to one project. 

Furthermore settings like the amount of wall loops, infill percentage and pattern, and printing speed for single layers can be applied. 
There are presets available for project specific parameters as well, however only globally, \ie they can only be applied to the entire project, not to specific objects within it.
As mentioned in the \href{https://github.com/SoftFever/OrcaSlicer/issues/7769}{OrcaSlicer Issue \#7769}, in particular for projects containing multiple objects, using presets is not a valid option. 


\begin{enumerate}
    \item create 3D model in Fusion
    \item export as 3mf file 
    \item open in OrcaSlicer
    \item set parameters
    \begin{itemize}
        \item apply system or user defined material presets, optionally setting up new presets
        \item apply settings (wall loops, infill percentage and pattern, layer speed etc.) manually per object or using presets globally (only available globally, not for single objects $\rightarrow$ \href{https://github.com/SoftFever/OrcaSlicer/issues/7769}{OrcaSlicer Issue \#7769})
        \item change type to Modifier / Support Blocker / Support Enhancer; in case of Modifier $\rightarrow$ apply settings accordingly
    \end{itemize}
\end{enumerate}

\subsubsection{The 3MF specification} \cite{3mf_consortium_3mf_2025}
\begin{itemize}
    \item ``3MF Document markup has been designed in anticipation of the evolution of this specification. It also allows third parties to extend the markup. Extensions are a critical part of 3MF, and as such, this core specification is as narrow as possible.'' [p.~8]
    \item 3MF = ZIP archive following the .ZIP File Format Specifications by PKWARE Inc. containing one or more 3D payloads
    \item 3D payload = ``complete collection of interdependent parts and relationships within a package'' consisting of ``a 3D object definition and its supporting files''

    \item PrintTicket $\rightarrow$ seems to be OS specific, so probably not helpful but \todo investigate further
    \item most important: 3D Model Part = root of 3D payload $\rightarrow$ ``contains definitions of one or more objects to be fabricated by 3D manufacturing processes''\cite[p.~6]{3mf_consortium_3mf_2025} $\rightarrow$ contains resource definitions (objects, materials) and items to be build 

    \begin{itemize}
        \item there MUST be exactly one <model> element in a 3D Model part
        \item a model must have two additional child elements: <resources> and <build>
        \item <resources> element
        
        provides a set of definitions that can be drawn from to define a 3D object; root element of a library of constituent pieces of the overall 3D object definition $\rightarrow$ objects, properties, materials; `object resource': 3d object that could be but will not be manufactured on its own
        
        \item <build> element
        
        provides a set of items that should actually be manufactured as part of the job; contains \texttt{<item>} elements = objects to be manufactured
    \end{itemize}
