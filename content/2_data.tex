\chapter{Description}\label{ch:data} 

\section{Definition of Problem} 

When designing and printing 3D models, there are a few steps being repeated over and over again. 
Usually the process consists of creating the 3D model in a CAD software like Autodesk Fusion and exporting it as an STL or 3MF file.
Next, this file is imported to a slicer software, where the printing parameters are being set. 
Since these parameters are not part of the exported file, the user has to potentially set them each time following modifications of the 3D model and reimporting it to the slicer. 
The printing parameters not only include the filaments, but also the surface that the object is placed on and possibly whether certain objects are to be handled as modifiers to the main 3D model.

\section{Research topic}

The goal of this bachelor thesis is to prove whether it is possible to export `print hints' within the 3MF file from Autodesk Fusion and have the slicer automatically parse them to make the working process described above more efficient and avoid repetitious manual steps.

\section{Solution approach }

Based on the current knowledge, the solution will consist of multiple parts. 
\begin{enumerate}
    \item It shall be possible to add print hints within Autodesk Fusion. Since this software is not open source, the only way to add this functionality would be as a script or plugin. Autodesk Fusion provides a comprehensive amount of methods within their API for developers to use. 
    \item The slicer shall then be able to detect the different materials from exported 3MF files and automatically map them to filament presets, as well as automatically handle print hints.  
    \item Furthermore it needs to be determined, whether the 3MF standard would need to be augmented or if the print hints can be written to the xml data without changing the file standard. 
\end{enumerate}

\section{Research methods}

Since the goal is a proof of concept, the methods used will mainly be to create software prototypes. 
Optionally it might be useful to conduct user surveys as to the usability of the created prototypes. 
Accompanying these, the written part shall illustrate the design decisions as well as any other important steps, serve as documentation and give the reader foundational knowledge regarding the design process for 3D models and the working of slicer software. 

\section{Current state of research}

Insights so far: 
\begin{itemize}
    \item Fusion exports materials as hexcode colours to the 3MF file where they are being referenced in each 3D object but not imported by the OrcaSlicer yet
    \item 3MF saves 3D models in easily human-readable XML format which is therefore easily edited 
    \item OrcaSlicer doesn't throw any errors when importing manually edited 3MF files 
    \item Fusion provides a comprehensive API to use for plugins or scripts 
\end{itemize}

The most important literature will certainly be Fusion's API documentation, as well as the documention of the OrcaSlicer and possibly the predecessors SliC3r, Bambu Studio and PrusaSlicer as far as available and up to date. 
Further literature is yet to be researched.
